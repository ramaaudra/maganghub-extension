# The product is named SakuMagang, and the name deliberately does not lead with "MagangHub"

The extension is named **SakuMagang** — one word, both capitals. It carries the manifest `name` (bare, with no descriptor suffix), the popup `<h1>`, and a toolbar icon: a white Geist "S" on a full-bleed Field Blue square with sharp corners, rendered from the DESIGN.md tokens by `scripts/render-icon.mjs`. The previous working title, "MagangHub Extension", is retired. "MagangHub" now appears only in the manifest `description` and in prose, where it names *the site this tool supports* rather than *the party who made this tool*.

The load-bearing reason is that the old name contradicted the product's own position. PRODUCT.md forbids implying affiliation with Kemnaker, and README states plainly that this is unofficial — yet "MagangHub Extension" reads exactly like a first-party companion app. The irony was sharp: a product whose entire reason to exist is "do not trust things that present themselves as official" was presenting itself as official. A name is the first trust claim a user evaluates, before any permission prompt, so it has to be the first place the posture holds. A standalone name says *I am a separate instrument you can audit*; a platform-led name says *I am part of them* — and that is the sentence the credential-harvesting helper sites need their visitors to believe.

Three things about the name are chosen, not incidental, and each has a rejected alternative behind it.

**"Saku" over an invented word or an English one.** The design system's north star is the Field Notebook (ADR-0008), and *buku saku* is the literal Indonesian for a pocketbook — a small reference you carry into the field. The name is the verbal form of a decision already made visually, not a new one. A coined name was rejected as a debt of meaning that only distribution can repay, and this product has no distribution: no store listing, no users, no telemetry, no marketing channel. A name that must be explained cannot be explained by anything here.

**"Magang" attached, despite a known collision.** "Saku" alone was the recommendation and was rejected by the user on solid grounds: this product is bound to one platform, and a name generic enough for any product wastes that specificity. The accepted cost is that *uang saku magang* — the Magang Nasional stipend — is one of the most-searched phrases in this exact domain, so "SakuMagang" will read to some users as a stipend tracker. This is a deliberate trade, not an oversight. It self-corrects within a second of opening the popup, which shows a list of Lowongan and nothing about money. The one-word spelling is part of the mitigation: the stipend phrase is always written spaced ("uang saku magang"), so `SakuMagang` closed up reads as a constructed mark rather than a fragment of that phrase. `Saku Magang` (spaced) reconstructs it and is banned; `sakuMagang` (camelCase) is an identifier convention, not a product name, and reads as a bug in the toolbar.

**Rejected outright, with reasons worth keeping.** A name asserting safety ("Aman…", "Jaga…") was rejected because PRODUCT.md principle 1 is *trust is a construction, not a claim* — the helper sites also claim to be safe, and putting the claim in the name converts a construction into a promise. Any `X for MagangHub` derivative was rejected for the same reason as the old name, only softer. **"catatGang"** was rejected primarily because `catat`/**Catatan** is a locked glossary term in CONTEXT.md; a product named for one of its own features makes sentences like "the Catatan in catatGang" unwritable and quietly breaks the vocabulary discipline the repo enforces everywhere else. Its wordplay also does not survive reading (nobody parses it as the tail of "magang"), "gang" reads as a criminal group in the Latin-script global reading a store listing gets, and its jokey register fights the "plain, direct, no alarm" voice.

**The icon is a monogram, and specifically not a star.** A star is the product's core gesture and the obvious choice — which is the trap. In the toolbar it would sit a few dozen pixels from Chrome's own bookmark star, two stars side by side meaning different things. CONTEXT.md already bans the word "bookmark" for Favorite as *"overloaded with browser bookmarks"*; a star icon is the visual form of the confusion the glossary bans verbally. A pocket silhouette was rejected for doubling down on the stipend collision and for being indistinguishable from an inbox tray at 16px; a notebook page was rejected as an unreadable grey rectangle at that size. The monogram wins on system rather than on drawing: a flat square at `--radius: 0rem` in one calm blue stands out among a toolbar of round, gradient-filled icons precisely because it belongs to a different class — which is ADR-0008's argument, applied at 16px. Two letters were rejected because "SM" at 16px leaves each glyph about 6px and Geist stops being Geist.

The icon is rendered through headless Chromium rather than hand-authored as an SVG so that `oklch()` and the real Geist Variable outline resolve exactly as they do in the popup; a hand-converted hex or a substituted system font is how an icon silently drifts out of the design system. Measured output: background `rgb(0, 105, 168)`, white-on-blue contrast 5.86:1, corners square to the pixel.

Consequences. `CONTEXT.md` now carries **SakuMagang** as a glossary term with its banned spellings, so the name is enforced by the same discipline as the domain vocabulary. PRODUCT.md's "Undecided" list loses the product-name and identity-asset entries and gains the repo/package identity in their place: the GitHub repository and `package.json` remain `maganghub-extension` on purpose — renaming the repo would break the public URL PRODUCT.md cites as its auditability proof, and a package name is never user-visible. Package name is not product name, and the two are allowed to differ. If the project ever publishes to the Chrome Web Store, three things must be revisited together: whether the listing title needs a descriptor suffix for search (the manifest `name` is bare today because nothing reads it but a tooltip), whether a Web Store name collision exists (unchecked, since there is no listing), and whether the repo should finally be renamed. The placeholder-free icon does not make the store artwork exist — screenshots and promo tiles remain absent, and no surface may imply otherwise.
